데이터가 공개되기까지

GitHub Pages는 정적 호스팅이라 서버 DB를 직접 연결할 수 없습니다. 그래서 이 PC에서 DB를 고친 뒤 검증하고 다시 배포합니다.

  1. 로컬 관리 화면

    이 PC에서만 열리는 화면에서 추가·수정·삭제

  2. SQLite DB

    저장할 때 글자 수와 규칙을 검사

  3. 검증

    글자 수, 증빙 파일, 개인정보 패턴 검사

  4. 정적 빌드

    공개 항목만 내보내 웹페이지 생성

  5. GitHub Pages

    빌드 결과만 공개 주소에 배포

공개 사이트에는 데이터를 바꾸는 경로가 없습니다. 방문자는 빌드된 웹페이지만 볼 수 있고, 내부 메모와 비공개 항목은 빌드 결과에 포함되지 않습니다.

테이블 관계도

프로젝트를 중심으로 기술, 증빙, 수치, 역량, 기업을 연결했습니다. 예를 들어 Skills 페이지의 기술별 프로젝트 목록은 project_technologies 연결 테이블에서 나옵니다.

좁은 화면에서는 구조도를 옆으로 밀어서 볼 수 있습니다.

데이터를 추가하고 수정하는 방법

아래 화면은 실제 관리 화면의 캡처입니다. 이 화면은 이 PC에서만 열리고 실행할 때마다 새 접속 토큰이 필요합니다. 공개 사이트에서는 열 수 없습니다.

  1. npm run admin으로 관리 화면을 엽니다.
  2. 항목을 추가·수정·삭제합니다. 저장 시 규칙을 검사하고 변경 이력을 남깁니다.
  3. npm run db:status로 등록 현황을 확인합니다.
  4. npm run deploy로 검증, 빌드, 배포를 실행합니다. 검증에 실패하면 배포되지 않습니다.

실제 파일과 동작 기록

구조와 동작을 직접 확인할 수 있는 자료입니다.

  • 스키마
    schema.sql

    테이블, 외래 키, 저장 규칙을 정의한 실제 파일입니다.

    공개
  • 데이터
    portfolio-public.db

    실제 DB에서 공개 항목만 옮긴 SQLite 파일입니다. 내부 메모와 비공개 행은 없습니다. DB Browser for SQLite 같은 무료 도구로 열 수 있습니다.

    공개
  • 실행 기록
    proof-log.txt

    DB 복사본에 추가, 수정, 삭제를 실행하고 매번 사이트를 빌드해 결과가 바뀌는지 확인한 기록입니다.

    공개
  • 원본 DB
    portfolio.db

    내부 메모와 비공개 항목이 있어 공개하지 않습니다. 요청하면 화면 공유로 보여 드릴 수 있습니다.

    비공개 보관

구현된 것과 구현하지 않은 것

기능상태비고
SQLite DB와 테이블 관계구현기존
글자 수 검사와 확인 전 수치의 공개 차단구현기존
로컬 관리 화면의 프로젝트·역량·증빙 추가, 수정, 삭제구현기존
관리 화면에서 직무, 프로젝트, 증빙 연결 수정구현이번 보완
프로젝트 진행 상태 열 (완료, 중단, 실패 등)구현이번 보완
DB 구조 페이지, 공개용 DB 내려받기, 동작 기록구현이번 보완
DB 수정 후 빌드 결과에 반영되는지 자동 확인구현이번 보완
공개 사이트에서 방문자나 관리자가 직접 편집제공하지 않음정적 호스팅이라 서버가 없음
DB를 고치면 공개 사이트에 자동 반영제공하지 않음배포 명령을 실행해야 반영됨
소개 문장과 일하는 방식 등 일부 서술의 DB 관리제공하지 않음페이지에 직접 작성
